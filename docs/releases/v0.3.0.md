EggOS 0.3.0 is the first release you can boot and type in. It starts to a desktop in a QEMU window, with a shell, a file manager, Settings and a text editor. It runs Linux programs, and Windows, macOS and Android programs on the architectures listed below. It also has a built-in MCP server, so AI agents can use it under grants you give. It is pre-alpha: to try, not to use. It runs in QEMU only, and every process runs as root.

## What's new
- **A shell and processes:**
  - Users can now boot to a shell prompt (`eggsh`) started by init as process 1, type at it on the console or in the desktop's terminal window, and power off or reboot cleanly (D98 to D108, D183).
  - Programs get descriptors, pipes, `fork`, `execve`, `wait4`, signals, job control, threads and futexes, and a line discipline on the console (D100 to D106, D181).
  - `eggsh` runs pipelines, redirections, `&&`, `||`, background jobs, scripts, `if`, `for`, `case` and functions (D107, D125, D181, D182).
  - Core utilities such as `ls`, `cat`, `cp`, `grep`, `ps` and `free` (D108, D125), and a command registry with `--json`, paging and `--dry-run` (D160, D163, D164).
- **The desktop and windows:**
  - A desktop with a wallpaper, a top bar and movable, resizable windows, drawn on a virtio-gpu display with virtio keyboard and mouse (D110 to D115, D126, D128).
  - Users can pick the Windows, macOS or Linux layout in Settings (taskbar, dock or top bar, launcher, desktop icons, window controls and shortcuts) and keep it across reboots (D132, D133).
  - Several terminal windows, a boot screen, 14 keyboard layouts, 2x display scale, mouse preferences, a Task Manager, virtual desktops and accessibility settings (D185 to D187, D195, D200, D204, D205).
  - Users can run EggOS with no screen at all (D144).
- **Linux programs:** static Linux programs run unmodified on all three architectures, and dynamic glibc and musl programs run with their own libraries (D117, D167, D188). Sockets, shared memory, `epoll`, `fork` with copy on write and file locks work (D138, D139, D169, D171). Wayland programs open windows on the desktop through `eggway`, EggOS's Wayland server, and SDL, GTK 3 and Qt Widgets apps are checked in CI (D140, D172, D176, D179).
- **Windows programs (x86_64 and aarch64):**
  - Console programs, and GUI programs with windows, buttons, text boxes, menus and file dialogs (D118, D121, D129, D145).
  - MSVC C runtime programs, C++ exceptions, and programs that start other programs (D146, D177, D189).
  - Real apps run, such as Pegs and AutoHotkey v2 (D174, D178).
  - On aarch64, x64 programs run through ahead-of-time translation (D191).
- **macOS programs (aarch64 and x86_64):** console programs, Objective-C programs on our own runtime and the core of Foundation, and AppKit apps built in code, such as CocoaGame. Swift console programs run on a first slice of the Swift runtime (D120, D123, D142, D147, D175, D180, D190).
- **Android console programs:** NDK programs run, static or dynamic, on aarch64 and x86_64 (D119, D188).
- **Apps install:** users can install, open and uninstall Windows, macOS and Linux apps from a program, an `.app` or a `.zip`, each with its own icon, and they stay across reboots (D134, D148, D196). The Windows and macOS layers are in the x86_64 and aarch64 release images (D152). `cargo xtask sample-apps` builds apps to try.
- **Files and EggFS:**
  - Users can keep files across reboots on a disk formatted with EggFS, our own journaled file system. It has symbolic and hard links, and `disk` checks, repairs and formats disks (D131, D170, D192).
  - A folder from your computer appears read-only at `/media/host` (D130).
  - A Files app browses, opens, copies, moves and trashes files (D135), and a Text Editor edits text (D149).
  - One clipboard is shared by every app (D197).
- **Networking and the clock:**
  - EggOS is on QEMU's network: DHCP, DNS, UDP, TCP, `ip`, `ping`, `nslookup` (D157, D158).
  - `fetch` downloads over HTTP and HTTPS, using our own TLS 1.3 client (D159).
  - The date and time are real, with time zones and a network clock set by hand (D150, D159, D194).
- **AI agents over MCP:**
  - Users can connect Claude Code or any MCP client and let it read files, processes, windows and apps (D136).
  - Grants let an agent also write and trash files, run programs and install apps (D137).
  - An agent can see and operate any app window, by pixels or as an element tree (D141, D143, D161, D162).
  - Each agent has its own grants, changed with `agent grant` and `agent revoke` or in Settings (D193).
  - Agents on other machines pair with a one-time code (D193).
  - Every call is logged, and `agentlog` shows it. The desktop shows an `Agent` chip while a client is connected (D156).
- **Settings:** panes for Appearance, Display, Keyboard, Mouse, Storage, Date & time, Agents and About (D132, D150, D185, D192, D193, D195).
- **Safety and speed:** a kernel memory reserve so a program that uses up memory cannot crash EggOS (D155), randomised program addresses and SMEP (D201), and a weekly performance pass (D216). Test programs build as one integration program per package, which keeps build folders small (D217, a change for developers only).

## Downloads
`cargo xtask release` writes these files, and `.github/workflows/release.yml` publishes them as the GitHub Release when the `v0.3.0` tag is pushed (new in this release):
- `eggos-0.3.0-aarch64.elf`, `eggos-0.3.0-riscv64.elf` and `eggos-0.3.0-x86_64.elf`: one kernel image per architecture, with its initramfs inside.
- `SHA256SUMS`: the checksum of each image.
- `run-eggos.sh` (macOS and Linux) and `run-eggos.ps1` (Windows PowerShell): start the image in QEMU.

## Try it
Follow [Try EggOS in the README](https://github.com/eggspot/EggOS/blob/v0.3.0/README.md#try-eggos). In short:
1. Install QEMU 8.2 or later.
2. Download into one folder the image for your machine, `SHA256SUMS` and the run script.
3. Run the script. It picks your architecture, checks the image against `SHA256SUMS` and boots it:

```
sh run-eggos.sh                       # a QEMU window with the desktop; the console here too
sh run-eggos.sh riscv64 --serial      # another architecture, no window: the console here only
.\run-eggos.ps1 -Arch x86_64 -Serial  # Windows PowerShell
```

Pass a folder with `--apps <folder>` to use its files at `/media/host` and install apps from it. Add `--mcp` to let Claude Code or another MCP client work with EggOS ([docs/mcp.md](https://github.com/eggspot/EggOS/blob/v0.3.0/docs/mcp.md)). A disk file next to the image keeps `/home` and `/Applications` across reboots. Quit with Ctrl-A, then X.

## Size and speed
The numbers are from [benchmarks/baseline.txt](https://github.com/eggspot/EggOS/blob/v0.3.0/benchmarks/baseline.txt), which CI checks every change against. How each is measured is in [docs/benchmarks.md](https://github.com/eggspot/EggOS/blob/v0.3.0/docs/benchmarks.md).

| Architecture | Image size (`release_image_bytes`) | Boot to prompt (`boot_to_prompt`, instructions) | Memory at the prompt (`idle_memory_bytes`) |
|--------------|------------------------------------|------------------------------------------------|--------------------------------------------|
| aarch64 | 8,159,544 bytes (7.8 MiB) | 1,802,320 | 602,112 bytes (588 KiB) |
| riscv64 | 5,263,952 bytes (5.0 MiB) | 1,760,800 | 532,480 bytes (520 KiB) |
| x86_64 | 7,993,648 bytes (7.6 MiB) | 2,348,339 | 610,304 bytes (596 KiB) |

- `boot_to_prompt` counts instructions on one CPU with the serial console only, under QEMU `-icount`. It is not wall-clock time.
- On the wall clock, boot to the prompt took about 120 ms on aarch64, 161 ms on riscv64 and 261 ms on x86_64 from QEMU's start, on CI's machines on 2026-10-29 ([docs/limitations.md](https://github.com/eggspot/EggOS/blob/v0.3.0/docs/limitations.md)). QEMU emulates the CPU without acceleration.
- The images carry a lot because the desktop, the Windows and macOS layers and the apps are in the base until the component manager makes them optional (D152, D214).

## What was tested
CI (`.github/workflows/ci.yml`) runs these jobs on every change, and a final `check` job fails if any failed:
- `fast`: formatting, `cargo xtask lint`, clippy, `cargo xtask docs` and `cargo test --workspace`.
- `qemu`: boots each architecture in QEMU and checks the result.
- `dynamic-linking`, `static-glibc`, `android-dynamic`: dynamic and static Linux and Android programs.
- `rustc-version`, `hello-crate`, `workspace-build`: the official Rust toolchain and cargo builds running inside EggOS.
- `sdl3`, `sdl-app`, `gtk-app`, `qt-app`: SDL, GTK 3 and Qt apps through `eggway`.
- `win32-app`, `autohotkey`, `windows-programs`: Windows programs and apps.
- `cocoa-app`, `macos-programs`: macOS programs and apps.
- `bench`: benchmarks against the committed baseline (report only; a result more than 2x slower fails).
- `hosts`: clippy, tests and builds on a second host set.
- `run-scripts-windows`: boots the release image through `run-eggos.ps1` on Windows.

The release workflow runs `cargo xtask release`. It builds each architecture's release image and boots it to the shell prompt before it writes the files.

Not tested: real hardware (QEMU only), and what is listed under Known limits.

## Known limits
Everything not listed here as working is in [docs/limitations.md](https://github.com/eggspot/EggOS/blob/v0.3.0/docs/limitations.md). The main points:
- QEMU only, with no acceleration. No real hardware, no other hypervisor, no UEFI or bootable disk image. Devices: serial, virtio-gpu, virtio input, virtio-blk, virtio-net and a real-time clock. No Wi-Fi, sound or USB.
- One user, root. There are no logins or file permissions yet.
- No component manager: the desktop and the Windows and macOS layers are in the base image and cannot be left out. The riscv64 image carries neither layer.
- iOS apps are not supported. Android runs console programs only, with no `.apk` or binder.
- Windows, macOS and Qt programs run only as far as the limitations page lists; GTK 4 and browsers do not run yet. Real apps run only where the page names them.
- Networking is IPv4 on one adapter. EggOS ships no HTTPS root certificates, so `fetch https://` needs roots you give in `/etc/ssl/roots.pem`. There is no Network pane in Settings yet.
- The root file system is read-only; `/home` and `/Applications` live on the disk. The host folder is read-only and limited by QEMU, to about 500 MB and about 250 names at its top level.
- The desktop is minimal: Files selects one item at a time, the Text Editor has no word wrap or replace, and the fonts cover ASCII, Latin-1 and `€`.
- `eggsh` has no `$((...))`, `printf`, `trap` or `getopts` yet.
- Not every capability has its CLI, GUI and MCP front-ends yet, and agents' `run` and `install` grants are full control of the machine.
