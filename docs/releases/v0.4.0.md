EggOS 0.4.0 builds on 0.3.0. It adds themes, 20 keyboard layouts, terminals that select, copy and paste, a first-run setup, a Network pane with a clock kept right from the network, a downloads window, structured MCP results, more Windows controls, C++ exceptions and the registry for Windows programs, plists, nibs and Objective-C exceptions for macOS programs, and the Windows and macOS layers as components you install only when you need them. It is pre-alpha: to try, not to use. It runs in QEMU only, and every process runs as root.

## What's new
- **Look and feel:**
  - Users can choose a light, dark or high-contrast theme, in Settings > Appearance, `settings set appearance.theme` or MCP. Apps get tooltips, menu bars and menu buttons, tables, multi-line text areas, horizontal scrolling and drag inside a window (D219).
  - 20 keyboard layouts, switched with a key, with Num Lock and Scroll Lock lights, set in Settings > Keyboard (D221).
  - A busy app shows a Working pointer; a hung one is marked "not responding" and can be ended from a dialog. EggOS can boot straight to the desktop (D222).
- **Terminals** reflow when resized, select, copy and paste (with bracketed paste), take their title and folder from the shell, and open console apps in a window of their own. New: `terminal -t` and `-e`, `stty`, and the pseudo-terminal's packet mode and `TIOCGPTPEER` (D223).
- **First run and accessibility:** a new machine walks through its setup on first boot. New settings: high contrast, reduce motion and sticky modifiers (Shift five times). Kernel messages are at `/dev/kmsg` (D224).
- **Devices:** About lists every device. Disks, the network, the agent console and the random device run on interrupts, virtio-blk keeps 15 requests in flight, and the random pool is reseeded from virtio-rng at boot (D220).
- **Network and downloads:** Settings > Network, a network indicator in the bar, a Downloads window with `download` to list, cancel and clear, and "Set automatically" in Date & time. It syncs at boot and every 24 hours, and a large correction is taken only after an HTTPS check (D225).
- **AI agents over MCP:** list tools, dry runs and errors return structured results (`structuredContent`, `outputSchema`) across the command model (D226). Agents can operate more Windows controls: the sideways wheel, chains of dialogs, list items and check states (D227). A password field's text is never shown to agents.
- **Windows programs (x86_64 and aarch64):**
  - Password and number edits, scroll bar controls, radio buttons, group boxes, word selection, cursors and `GetOpenFileNameA` (D228).
  - C and C++ programs run on EggOS's own math library and more of the CRT: `setjmp`/`longjmp`, locales, wide streams and text mode (D229).
  - C++ exceptions, `dynamic_cast`, `typeid`, msvcp140 and threads, on x86_64 and ARM64 (D230).
  - JPEG, GIF, TIFF and ICO images. The Windows registry is kept on disk and can be edited from programs, the `windows registry` command, MCP and Settings > Windows (D231).
- **macOS programs:** plists, nibs, notifications, UUIDs, string encodings, run loop modes and `NSFileManager` (D232); `NSButton` types, `NSCursor` and `NSPasteboard` (D233); Objective-C exceptions through DWARF unwinding (D234).
- **Components** (D235): the Windows and macOS layers are no longer in the base image. They are the `windows-apps` and `mac-apps` components, in a component store that ships beside each image. Users install and remove them with `component install` and `component remove`, from `app install`'s offer when an app needs one, from MCP, or in Settings > Components. A component installs from the store attached read-only, each file checked against its SHA-256, and stays across reboots.
- **For developers:** one kernel tree serves every architecture, with each one's Linux facts in `kernel/src/linux/abi/<arch>.rs` (D218). The kernel denies holding a lock through a `match` on it (`clippy::significant_drop_in_scrutinee`), which found and fixed two deadlocks.

## Downloads
`.github/workflows/release.yml` runs `cargo xtask release` when the `v0.4.0` tag is pushed and publishes these files:
- `eggos-0.4.0-aarch64.elf`, `eggos-0.4.0-riscv64.elf` and `eggos-0.4.0-x86_64.elf`: one kernel image per architecture, with its initramfs inside.
- `eggos-0.4.0-aarch64-components.img`, `eggos-0.4.0-riscv64-components.img` and `eggos-0.4.0-x86_64-components.img` (new in this release): each architecture's component store. The x86_64 and aarch64 stores offer the Windows and macOS layers. riscv64's is empty, because neither layer runs there.
- `SHA256SUMS`: the checksum of each image and store.
- `run-eggos.sh` (macOS and Linux) and `run-eggos.ps1` (Windows PowerShell): start the image in QEMU, with the store attached when it is in the same folder and matches `SHA256SUMS`.

## Try it
Follow [Try EggOS in the README](https://github.com/eggspot/EggOS/blob/v0.4.0/README.md#try-eggos). In short:
1. Install QEMU 8.2 or later.
2. Download into one folder the image for your machine, its components store, `SHA256SUMS` and the run script.
3. Run the script. It picks your architecture, checks the image and the store against `SHA256SUMS` and boots it:

```
sh run-eggos.sh                       # a QEMU window with the desktop; the console here too
sh run-eggos.sh riscv64 --serial      # another architecture, no window: the console here only
.\run-eggos.ps1 -Arch x86_64 -Serial  # Windows PowerShell
```

To run Windows apps, type `component install windows-apps` (or use Settings > Components) once; `mac-apps` does the same for macOS apps. Pass a folder with `--apps <folder>` to use its files at `/media/host` and install apps from it. Add `--mcp` to let Claude Code or another MCP client work with EggOS ([docs/mcp.md](https://github.com/eggspot/EggOS/blob/v0.4.0/docs/mcp.md)). A disk file next to the image keeps `/home`, `/Applications` and installed components across reboots. `--no-components` boots without the store. Quit with Ctrl-A, then X.

## Size and speed
The numbers are from CI's benchmark run on the release's code (pull request #154). How each is measured is in [docs/benchmarks.md](https://github.com/eggspot/EggOS/blob/v0.4.0/docs/benchmarks.md).

| Architecture | Image size (`release_image_bytes`) | Component store (`components_store_bytes`) | Boot to prompt (`boot_to_prompt`, instructions) | Memory at the prompt (`idle_memory_bytes`) |
|--------------|------------------------------------|----------------------------------------------|------------------------------------------------|--------------------------------------------|
| aarch64 | 5,992,496 bytes (5.7 MiB, 0.3.0: 7.8 MiB) | 3,932,160 bytes (3.8 MiB) | 2,043,408 (0.3.0: 1,802,320) | 688,128 bytes (672 KiB, 0.3.0: 588 KiB) |
| riscv64 | 6,312,904 bytes (6.0 MiB, 0.3.0: 5.0 MiB) | 4,096 bytes (empty) | 1,897,900 (0.3.0: 1,760,800) | 602,112 bytes (588 KiB, 0.3.0: 520 KiB) |
| x86_64 | 6,276,920 bytes (6.0 MiB, 0.3.0: 7.6 MiB) | 3,665,920 bytes (3.5 MiB) | 2,605,087 (0.3.0: 2,348,339) | 688,128 bytes (672 KiB, 0.3.0: 596 KiB) |

- **Smaller where the layers ran.** The x86_64 and aarch64 images are 21% and 27% smaller than 0.3.0's, because the Windows and macOS layers moved out of the base into the component store, which you download only if you want them.
- **Bigger on riscv64.** Its image never held the layers, so it carries only what this release adds to the base: the terminals, themes, keyboard layouts, first run, the Network pane, downloads and the clock keeper.
- **Slower boot, more memory.** Boot to the prompt takes 8% to 13% more instructions and the prompt uses 13% to 14% more memory on every architecture, for the same additions. These are above CI's baseline, so the weekly performance pass traces and trims them (D122).
- `boot_to_prompt` counts instructions on one CPU with the serial console only, under QEMU `-icount`. It is not wall-clock time.

## What was tested
CI (`.github/workflows/ci.yml`) runs these jobs on every change, and a final `check` job fails if any failed:
- `fast`: formatting, `cargo xtask lint`, clippy, `cargo xtask docs` and `cargo test --workspace`.
- `qemu`: boots each architecture in QEMU and checks the result. New in this release: the terminals, first run, network indicator, downloads, HTTPS clock, Windows controls and component checks, with the component test installing and removing the Windows layer from the store and through Settings.
- `big-endian-tests` (new): the byte-order-sensitive crates' host tests on a big-endian target.
- `dynamic-linking`, `static-glibc`, `android-dynamic`: dynamic and static Linux and Android programs.
- `rustc-version`, `hello-crate`, `workspace-build`: the official Rust toolchain and cargo builds running inside EggOS.
- `sdl3`, `sdl-app`, `gtk-app`, `qt-app`: SDL, GTK 3 and Qt apps through `eggway`.
- `win32-app`, `autohotkey`, `windows-programs`: Windows programs and apps, including the MSVC C and C++ test programs on x86_64 and aarch64.
- `cocoa-app`, `macos-programs`: macOS programs and apps, including Objective-C exceptions.
- `bench`: benchmarks against the committed baseline (report only; a result more than 2x slower fails).
- `hosts`: clippy, tests and builds on a second host set.
- `run-scripts-windows`: boots the release image through `run-eggos.ps1` on Windows.

The release workflow runs `cargo xtask release`. It builds each architecture's release image and component store and boots each image to the shell prompt before it writes the files.

Not tested: real hardware (QEMU only), and what is listed under Known limits.

## Known limits
Everything not listed here as working is in [docs/limitations.md](https://github.com/eggspot/EggOS/blob/v0.4.0/docs/limitations.md). The main points:
- QEMU only, with no acceleration. No real hardware, no other hypervisor, no UEFI or bootable disk image. Devices: serial, virtio-gpu, virtio input, virtio-blk, virtio-net, virtio-rng and a real-time clock. No Wi-Fi, sound or USB.
- One user, root. There are no logins or file permissions yet.
- Components cover the Windows and macOS layers only: the desktop and the built-in apps are still in the base image. Components install only from an attached store, not from the network.
- iOS apps are not supported. Android runs console programs only, with no `.apk` or binder.
- Windows, macOS and Qt programs run only as far as the limitations page lists. GTK 4 and browsers do not run yet. Windows programs have no tray icons, hooks, layered windows or WinINet. Window scroll bars and one shared file picker are not built yet.
- Networking is IPv4 on one adapter. EggOS ships no HTTPS root certificates, so `fetch https://` and the clock's HTTPS check need roots you give in `/etc/ssl/roots.pem`.
- The root file system is read-only; `/home`, `/Applications` and `/var` live on the disk. The host folder is read-only and limited by QEMU, to about 500 MB and about 250 names at its top level.
- The desktop is minimal: Files selects one item at a time, the Text Editor has no word wrap or replace, there is no drag and drop between apps, and the fonts cover ASCII, Latin-1 and `€`.
- An agent holding the write grant can change a Windows registry value through MCP without being asked first (D231).
