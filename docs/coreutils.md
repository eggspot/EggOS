# The EggOS core utilities

`userland/coreutils` (D108) is one program, `/bin/coreutils`, with the utilities as hard links
to it in `/bin`: `agentlog`, `cat`, `chmod`, `cp`, `date`, `device`, `df`, `echo`, `false`, `fetch`, `free`, `grep`, `halt`,
`head`, `hwclock`, `ip`, `ln`, `ls`, `mkdir`, `mv`, `nslookup`, `ping`, `poweroff`, `ps`, `readlink`,
`reboot`, `rm`, `sleep`, `tail`, `tee`, `touch`, `trash`, `true`, `uname`, `uptime`, `wc` and `wm`
(D108, D125, D128, D135, D136, D137, D150, D157, D158, D170, D171). It runs the utility named by the last component of the name
it was started by, so `ls`, `/bin/ls` and a link called `ls` anywhere are all `ls`. Started as `coreutils`, it runs
the utility its first argument names (`coreutils ls /`); `coreutils --list` lists them. It is
our own Rust program on our own runtime, like the shell: no C library, no allocator, about
45 KiB, and every name costs only a directory entry in the initramfs.

The shell's builtins (`echo`, `true`, `false`, docs/shell.md) still run first; the programs are
what `PATH` finds for everything else, and what other programs start (`/bin/echo`).

## The utilities

Options can come before or after operands, and `--` ends them, as GNU's do. An error is
written to standard error as `utility: what: why`, the way GNU's are worded, and sets the exit
status; a bad option is `invalid option -- 'x'` (or `unrecognized option '--x'`). When one
command fixes the error, a second line says it: `  try: wm list` (D160).

The command model (D160, D163, docs/ux/command-model.md) describes every command in its
registry (`userland/commands`): each utility here, `app`, `wm`, `edit`, `settings` and
`terminal` (D187: opens a terminal window running the shell and returns at once). `help`
lists them, `help <words>` shows one's usage, options, error codes, examples and GUI, and
`help --json` writes the definitions as JSON lines. The examples run as tests against the
utilities' fake system, so they are what the commands print. Every utility reads its options
from its definition except `date`, `hwclock`, `ip`, `nslookup`, `fetch`, `echo`, `trash`,
`agentlog` and `wm`'s verbs other than `list`, whose own parsers take the same options (D165). `ls`, `ps`, `wm list`, `wm show`, `app list`, `agentlog`,
`help`, `wc`, `free`, `uptime`, `uname`, `readlink`, `df`, `device list` and `settings list|get` take `--json` (`ip` its `-j`): one JSON record per line on standard output, and each error as one line
`{"error":{"code":"...","category":"...","message":"...","fix":"...","fix_command":"..."}}` on
standard error, with the same exit status as in text. In `eggsh`, `help` alone describes the
shell; with words it runs `/bin/help`.

Lists come in pages (D164): `ls`, `ps`, `wm list` and `app list` take `--limit <count>` (at
most 500 entries for `ls`, 100 items for the others) and `--after <cursor>`. A page holds the
next items by their key (a name, a process or window id) after the cursor; when more follow,
the last line on standard error is `more: --after <cursor>`, the cursor being the page's last
key with any byte outside letters, digits and `._~@+,=:-` (and a leading `-`) written as
`%XX`, so `ls --after 'my%20notes'` goes on after `my notes`. With `--json` that line is
`{"page":{"truncated":true,"truncated_by":"limit","next_cursor":"<cursor>"}}`. The exit status
stays 0; a cursor that is not one is `bad_cursor` (a usage error). `trash`, `app uninstall`
and `settings set` take `--dry-run`: they check what they can, say what they would do, and
change nothing.

| `ls [-aAdlC1] [--json] [--limit count] [--after cursor] [path...]` | Lists each directory's entries, sorted by name (byte order), without names starting with `.` unless `-a` (all, `.` and `..` included) or `-A` (all but those two). A name's width is its count of characters, not bytes. The operands that are files get columns of their own, then each directory. With no operand, `.`. `--json` writes a record per entry instead, with `name`, `path`, `type` (`file`, `folder`, `link`, ...), `permissions`, `links`, `owner`, `group`, `size_bytes` and `modified_at` (RFC 3339, UTC), and no headers or totals (D160). `--limit` and `--after` page one directory's entries by name however many it holds (D164): it keeps only the smallest names past the cursor while it reads. | 0; 1 if an entry could not be examined or, without `--limit`, a directory has more than 1024 entries or 32 KiB of names (the listing is cut short and says so); 2 if an operand could not be reached or a directory not read, for a bad option, a bad cursor, or `--limit` with several operands or `-d` |

| `chmod [-Rv] mode file...` | Sets each file's permission bits (D170), as GNU's: `mode` is octal (`755`, `4755`) or symbolic, comma-separated clauses `[ugoa]*[+-=][rwxXst]*` (`u+x`, `go-w`, `a=rX`, `g=u` copying the owner's bits), `X` meaning execute only for a directory or a file someone may already execute, `s` and `t` the set-id and sticky bits. Without `u`, `g`, `o` or `a`, the bits of the umask (EggOS's fixed `022`) are left alone, so `chmod +x f` gives `755` on a `644` file and `chmod -w f` leaves the group's and others' write bits. A symbolic link named is followed (its target changes); `-R` (`--recursive`) changes a directory and everything in it, leaving the symbolic links met inside alone (never followed, never changed), and does not walk into a link named. `-v` (`--verbose`) says `mode of 'f' changed from 0644 (rw-r--r--) to 0755 (rwxr-xr-x)` or `retained as`. | `ping [-c count] [-i interval] [-W timeout] [-s size] [-q] host` | Sends ICMP echo requests to `host` (an IPv4 address, `localhost`, or a name resolved with `/etc/resolv.conf`'s servers) through a ping socket (D157): `count` of them (4 by default, so it ends), one every `interval` seconds (1, at least 0.2), each waited for `timeout` seconds (1), with `size` bytes of data (56). | `nslookup [-port=<port>] [-timeout=<seconds>] name [server]` | Asks a DNS server (the first of `/etc/resolv.conf`'s, or `server`, an IPv4 address, at `port`, 53 by default) for `name`'s IPv4 addresses (D157), twice, waiting `timeout` seconds (2) each time, and writes BIND's layout: `Server:`, `Address: 10.0.2.3#53`, then `Non-authoritative answer:` with a `Name:` and `Address:` line per address (and `canonical name =` for an alias); `** server can't find name: NXDOMAIN` (or `SERVFAIL`, `REFUSED`) and `;; connection timed out; no servers could be reached` otherwise. Looking up an address's name is not supported yet. | 0; 1 when nothing was found or for a bad usage |
| `fetch [-q] [-o <file>] [--] <url> [<file>]` | Downloads an `http://` or `https://` URL (D158, D159): looks the host up as `ping` does, connects (10 seconds at most), sends a `GET` (HTTP/1.1, `Connection: close`), skips interim answers, follows up to 5 redirects (a whole `http://` URL or a path on the same host), and writes the body, by its length, in chunks or until the server closes, to `file` (`-o file`, or a second operand; `-` is standard output) or to standard output. With a file it says `Saved <n> bytes to <file> (HTTP <status> <reason>)` unless `-q`. A 4xx or 5xx status is an error (`fetch: host:port/path: 404 Not Found`), as are an answer that stops for 30 seconds or a connection that closes before the whole body. An `https://` URL is fetched over TLS 1.3 (D159): the server's certificate must name the host, be valid now and lead to a trusted root in `/etc/ssl/roots.pem` (or `/media/host/roots.pem`); EggOS ships none (see docs/network.md), and a failed check names its reason. | 0; 1 on any error |
| `hwclock [-r\|-w\|-s] [-u]` | The hardware clock (D150), read from `/proc/driver/rtc`: `-r` (`--show`, the default) writes its time as `2026-10-29 14:05:09+00:00`; `-w` (`--systohc`) sets it to the system clock; `-s` (`--hctosys`) sets the system clock to it. Setting the clock any other way (`date -s`) sets the hardware clock too. | 0; 1 with no hardware clock (`no hardware clock: /proc/driver/rtc is missing`), when it cannot be read, or when the kernel refuses |
| `poweroff`, `reboot`, `halt` | Ask init to power the machine off, reset it or halt it (D183): init sends every other program `SIGTERM` (and `SIGCONT`, so a stopped one sees it), sends those left after 3 s `SIGKILL`, waits 1 s more at most, puts the disks' changes on them and calls `reboot(2)`. The request is systemd's signal to process 1 (`SIGRTMIN+4` powers off, `+5` restarts, `+3` halts). If init has not taken the machine down 2 s later (no init that answers), the utility says so and does it itself. `-f` and `--force` skip init: `sync`, then `reboot(2)` at once. Root only. | Does not return; 1 with the error when init or the kernel refuses |

## Limits and differences from GNU

- Lines are read in pieces of 16 KiB: `grep` and `head` treat a longer line as several. The
  text utilities flush their output before each read, so `cat | grep x` shows each match as it
  is typed.
- `cp` has no `-p`, `-i` or `-n`, and `cp -r` does not merge into an existing directory;
  `rm` asks nothing (no `-i`); `grep` has no `-E`, `-r`, `-o`, `-l` or back-references; `touch` sets only the
  modification time (no access time is kept, no `-d` or `-r`).
- Started with `EGGOS_NO_SYMLINKS=1` in its environment, which the MCP server gives the twins of
  its path tools (D170, docs/mcp.md), every utility refuses a symbolic link anywhere on a path it
  opens or changes (`Too many levels of symbolic links`): files are opened with `openat2`'s
  `RESOLVE_NO_SYMLINKS` and `RESOLVE_NO_MAGICLINKS`, and a path is made, removed, renamed, linked,
  read as a link, touched, given a mode (`fchmodat2` with `AT_SYMLINK_NOFOLLOW`) or examined through its folder opened that way and the `*at` call on
  its last part (which is never followed: `ls -l` shows a link as a link). Walks such as `rm -r`
  and `trash` of a folder go through the same calls. Without the variable, links are followed as
  everywhere else.
- `chmod` has no `-c`, `-f`, `--reference`, `-H` or `-L`, and an octal mode clears the set-id bits of a
  directory as it does a file's; `ln` has no `-i`, `-b`, `-L`, `-P`, `-r` or `-t`; hard links never follow a symbolic link given as
  the target (GNU's `-P`).
- `cp`, `mv`, `mkdir`, `rm` and `trash` are the command line of what Files does with a
  window (D135); `trash` is also the MCP tool `trash` (D137), while `cp`, `mv`, `mkdir` and
  `rm` have no MCP tools yet (an agent with the `run` grant runs them, docs/mcp.md); the other
  utilities' GUI front-ends come with the capability framework (M14).

- `ls` shows owners and groups as numbers (there is no user database yet), times always as
  `YYYY-MM-DD HH:MM` in UTC (GNU's `--time-style=long-iso`; there is no time zone database),
  no colours, no `-x` (columns across) or `-w`, does not read `COLUMNS`, counts a wide
  character (CJK, emoji) as one column, and writes control characters in names as they are. It holds one directory at a time:
  1024 entries and 32 KiB of names. A command takes at most 256 arguments.
- `poweroff`, `reboot` and `halt` go through init, which has no services to stop in order:
  every program gets `SIGTERM` at once, and the 3 s and 1 s waits are fixed (no `shutdown`
  with a delay or a message to users, no `wall`).
- `sync` takes no operands: it puts every file system's changes on the disk (D131).
- `echo` takes no escapes (`-e`), like the shell's builtin; `sleep` takes no `inf`.
- `date` knows UTC only (no `TZ`, no time zone database, no `-d` to read a date, no
  `MMDDhhmm` operand to set one, no `%N` or `%:z`); `hwclock` has no `--adjust`, drift
  file or local-time hardware clock, and reads `/proc/driver/rtc` rather than `/dev/rtc0`.
